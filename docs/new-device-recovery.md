# 新设备接入与恢复设计（0.11.0）

## 用户路径

- 日常设置：在两台设备开启相同分组的同步，解锁后新设备可直接“接收云端设置”。本机独有项目保留，双端修改仍需选择；引用型 Key 的并发保护和默认关闭的独立加密开关不变。
- 历史备份：连接信息保存后查找备份；“备份与恢复”页签内唯一的“恢复备份”入口提供选择、检查、安装缺失插件、离线确认三步。逐文件原样恢复保留在高级选项中。

## 迁移规则

新设备向导只处理一个明确选择的源 profile，映射到当前运行的目标 profile。包清单保留目标现有字段、额外依赖和 bundle；默认使用本机已有依赖声明。源依赖可携带普通版本范围，范围提示不会单独阻止恢复。

旧设备的本地路径、Git/tarball 等特殊来源不自动安装。对应插件已在目标清单中声明时，用户选择保留本机版本，向导使用该声明；未安装时列出具体包名，需检查可信来源。npm 查找只返回精确版本供确认，安装调用 Harness `pluginManager.inspect` / `installBundle`，`enabled:false, saveExact:true`，不自动批准构建脚本、卸载其他包或启用备份清单。

源安装脚本、pnpm 策略、覆盖规则、锁文件和全局补丁不导入。现有目标的 base/web/acp/headless/sdk 启动 bundle 保留，不因迁移另一个 profile 而改变启动方式。所选 profile 的配置补丁仍是文件级替换：机器路径和可执行表达式只提示，不声称已经转换；不认识的第三方插件配置也不会被自动解释。

## 在线与离线边界

页面中的检查不改写 profile；“确认安装”是用户单独授权的 Harness 包管理操作。安装后重新计算预览，防止旧预览继续生效。

“生成离线恢复步骤”把已校验的备份与选择加密保存在目标 home 的 `config-vault/restore-request-<UUID>.vault`，不包含 WebDAV 密码、Key 凭据文件或口令。口令仅用于此次向导，生成任务、关闭或切换到其他页签后清空。公开 DTO 不包含配置正文。

系统终端使用一条 `finish-restore --home ... --request ... --offline` 命令，隐藏输入口令后重新计算完整计划，显示文件变化，要求用户输入“确认恢复”。不需要 WebDAV 连接、环境变量导出或复制确认码。准备后文件发生任何变化都会拒绝执行，需重新在页面预览。`--offline` 仍是用户对停止相关进程的明确声明，插件不声称能发现或退出所有外部进程。

最终文件写入继续使用原有恢复锁、前置哈希检查、加密回退日志与失败回滚。唯一增加的本地依赖例外是：只允许保持目标中原已存在且声明完全一致的本地依赖；不能借此导入旧设备的新路径。原样恢复默认仍保留原来的阻止规则。成功后删除临时恢复任务，保留加密回退记录。

失败后的恢复任务保持加密供重新检查；当前 UI 没有任务管理/清理页。回退继续使用现有离线 `recover` 流程，尚无在线撤销按钮。

## 参考与取舍

研究了 [Magpie 的可迁移数据和接入/撤销](https://github.com/yetone/magpie/blob/main/docs/subsystems/sync-backup.md)、[Joplin 的数据项同步](https://joplinapp.org/help/dev/spec/sync/)、[Remotely Save 的三方比较和删除保护](https://github.com/remotely-save/remotely-save/blob/master/docs/sync_algorithm/v3/design.md)、[DejaVu 的版本索引](https://github.com/siyuan-note/dejavu)。没有复制其代码。

Harness 插件尚不能像宿主应用一样完整管理任意第三方状态；因此没有承诺无差别的在线整机恢复。现阶段明确区分受支持字段的在线接收和经检查的离线配置迁移，不将两者混成一个“强制覆盖”按钮。尚不支持把未发布的本地插件二进制、技能/MCP 文件、聊天记录或账号登录状态从备份中找回；这些内容本来就不在当前备份格式中。
